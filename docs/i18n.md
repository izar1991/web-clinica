# Traducció automàtica

El projecte manté el castellà com a font i fitxers de traducció versionats a `src/i18n/translations/`. Cada fitxer conté un `_meta.sourceHash` per detectar canvis en el catàleg font.

## Comprovar pendents

```sh
npm run i18n:check
```

Aquesta ordre no modifica fitxers ni necessita xarxa. Retorna error si hi ha claus sense traducció o si el catàleg font ha canviat des de l’última sincronització.

## Sincronitzar

```sh
TRANSLATION_ENDPOINT=https://example.invalid/translate npm run i18n:sync
```

L’endpoint ha d’acceptar una petició `POST` JSON amb `q`, `source` i `target`, i retornar `translatedText` o `translation`. Els locals regionals es transformen als codis habituals del proveïdor: `en-GB` a `en`, `de-DE` a `de`, `fr-FR` a `fr` i `zh-CN` a `zh`.

Sense `TRANSLATION_ENDPOINT`, la sincronització no escriu res. Això permet fer builds reproduïbles i sense dependència d’un servei extern.

Les traduccions existents es conserven. Quan el castellà canvia, la clau queda pendent de regeneració i la traducció anterior no s’elimina. El contingut mèdic ha de passar una revisió humana abans de canviar el seu estat a `reviewed` o `approved`.

## Estat actual

El catàleg inicial cobreix la interfície compartida. La migració següent ha de portar les pàgines i les dades mèdiques cap a aquestes claus abans d’activar la publicació dels nous idiomes.
